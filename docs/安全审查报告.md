## 二、已修复

### 🔴 1. 匿名客户端可领取会话令牌并直接调用资金接口

**复现（修复前）**

```bash
curl /api/session          → 200 {"ok":true,"token":"6e59…"}
curl /api/snapshot -H 'X-Bank-Session: …'  → 200 全量账户
curl /api/transfer -X POST … → 200 转账成功
```

`isSameOrigin()` 在**没有 Origin 头**时直接返回 true，等于对 curl/脚本完全敞开；令牌一发，所有客户端校验（密码、短信、T4 复核）全部绕过。

**修复**：新增 `isSameOriginStrict()`，要求 `Origin` 或 `Referer` 的 host 与 `Host` 一致，二者都缺失一律 403；`/api/session`、全部 `/api/*`（health 除外）、AI 代理都用它。

**验证**

```
匿名 curl：领取令牌 403 ✅
浏览器页面内：session 200 / snapshot 200 / transfer 200 ✅
```

### 🔴 2. 转账绕过用户设置的单笔/日累计限额

用户在「卡片管理 → 交易限制」里设了限额，但 `transfer.execute` 工具与 `/api/transfer` 都**没有校验**，直接转账可超出限额。

**修复**：前端 `transfer.execute` 与后端 `/api/transfer` 双门禁：

- 单笔：`amount > txnLimit.single` → 拒绝
- 日累计：`transferDaily.amount + amount > txnLimit.daily` → 拒绝；成功后累计当日金额

**验证**

```
限额 单笔2000/日5000
转 5000 → 超过单笔限额 ¥2,000.00 ✅
转 1500 → ok ✅
```

### 🟠 3. 人工复核「通过」无验证（可自批 T4）

`adminApproveReview()` 直接执行并扣款，用户在「复核审批」页自己点【通过】即可绕过 T4 大额复核。

**修复**：`adminApproveReview` 执行前强制 `showSecurityVerification`（交易密码），未通过则不执行、状态保持「待人工复核」。

**验证**：调用后弹安全验证；密码未输入时复核状态仍为「待人工复核」✅

## 三、仍然存在（需产品/部署决策）

### 🟡 4. 登录态（已删除，按需求回退）
登录页与 /api/login 已移除，改回「同源页面可领取令牌」。这是明确的演示取舍：公网部署时必须自行加访问控制（反代 Basic Auth / 内网访问 / 登录网关），否则任何能打开页面的人都可调用资金接口。

### ✅ 5. 服务端 T3 验证（已修）
新增 `POST /api/verify/issue`：客户端密码/短信/指纹验证通过后换取一次性令牌（5 分钟有效）；`/api/transfer`、`/api/wealth/buy`、`/api/wealth/redeem` 金额 ≥ ¥5,000 必须携带 `X-Bank-Verify`，令牌一次性（重放被拒）。
实测：无令牌 6000 转账被拒 → 错误 PIN 拒绝 → 正确 PIN 拿令牌后成功 → 重放同一令牌被拒。

### ✅ 6. 资金类接口频控（已修）
`/api/transfer`、`/api/transfer/reverse`、`/api/wealth/*`、`/api/card/*` 按 IP 滑动窗口限流：每分钟 20 次，超出返回 429。

### 🟢 7. 前端余额可用 localStorage 篡改
demo 数据本地优先，服务端快照会覆盖，但离线时显示可被改。**建议**：展示层统一以服务端快照为准（已部分实现），关键校验只在服务端。

### 🟢 8. 无并发/幂等覆盖全部资金接口
`/api/transfer` 有幂等键，`wealth.buy/redeem`、订阅、鲜花没有。**建议**：统一 `idempotencyKey`。

### 🟢 9. `/api/reset`（已加可选保护）
设置环境变量 `BANK_ADMIN_TOKEN` 后，reset 需带 `X-Bank-Admin` 头；未设置时保持演示可用。

### 🟢 10. XSS 面
用户输入（备注/贺卡/地址）多数已 `escapeHtml`，折叠提示函数 `guideConfirmCardCollapse(text)` 直接拼 HTML（当前只传内部常量）。**建议**：该函数内部转义，防将来传入用户输入。

## 六、资金操作安全优化（第二轮）

| 优化项 | 实现 | 效果 |
|---|---|---|
| T4 大额转服务端复核 | `/api/transfer` 金额 ≥ ¥50,000 不再扣款，写入 `manualReviews`（状态待人工复核） | 即使拿到令牌也无法绕过 T4 直接转走大额，余额不变 |
| 调额审批加锁 | `/api/card/limit/approve` 必须携带一次性验证令牌 + 申请处于「待人工复核」+ 审批额度与申请一致 | 不能无验证直接改额度 |
| 专项预留冻结加固 | `/api/fund/create` 金额 ≥ ¥5,000 需验证令牌 | 冻结资金也要过安全验证 |
| 资金审计日志 | 新增 `auditLog()`：转账、理财申购、调额审批、专项预留、大额复核全部留痕（时间/动作/金额/对象/IP/结果），最多保留 500 条 | 可追溯；新增 `GET /api/audit` 查询 |
| 理财幂等 | 申购/赎回支持 `idempotencyKey`，重复提交返回首笔结果 | 防双击/重试重复扣款 |

### 后续可继续优化（未实施）

1. **会话安全**：绑定 IP/UA、支持「退出登录」、并发会话数限制、异常刷新告警。
2. **登录**：失败 5 次锁定 10 分钟、密码加盐哈希（当前明文比对）、可选短信二次验证。
3. **复核工作流**：复核通过改为服务端执行（当前为客户端点击后调工具），增加驳回原因与时间线。
4. **数据加密**：SQLite（`data/bank.db`）落盘加密（SQLCipher）、`config.local.js` 用系统密钥库或环境变量注入。
5. **并发与一致性**：写接口加版本号（乐观锁），避免多标签页同时操作导致余额覆盖。
6. **资金展示脱敏**：卡号/手机号统一脱敏，日志不落明文敏感字段。
7. **风控规则扩展**：收款人首次交易冷静期、常用设备校验、单日新增收款人上限。
8. **可观测性**：资金操作指标（成功率/拦截率/复核率）+ 异常告警。

### 第二轮优化（资金与信息安全）

### 分级规则调整（按业务要求）

| 档位 | 金额 | 确认卡 | 验证方式 | 服务端 |
|---|---|---|---|---|
| T1 | < ¥999 | 必须 | 指纹 / 交易密码（弹窗，演示密码 123456） | 免令牌 |
| T2 | ¥1,000–9,999 | 必须 | 短信验证码（演示 123456） | 需一次性验证令牌 |
| T3 | ¥10,000–99,999 | 必须 | 短信验证码 + 人脸确认（模拟识别约 2 秒） | 需一次性验证令牌 |
| T4 | ≥ ¥100,000 | 必须 | 短信 + 人脸 + 人工复核 | ≥¥100,000 服务端直接转复核，不扣款 |

- 可疑度仍可抬高档位：中风险至少 T2、高风险至少 T3。
- 服务端阈值同步为 ¥1,000（需令牌）与 ¥100,000（转复核）。
- 人脸与指纹均为演示模拟（点击/等待即通过），真实环境需接入活体检测 SDK。

## 七、服务端化资金逻辑（进行中）

### 已完成：转账判定与执行回服务端

| 环节 | 之前 | 现在 |
|---|---|---|
| 风险评分 / 档位 | 前端 `agentAssessTransferRisk` 计算 | **服务端 `/api/transfer/prepare`** 计算，前端只展示 |
| 限额 / 余额 / 上限 | 前端先判，服务端再判 | 服务端预判直接拒绝（`无法发起转账` + 原因） |
| 扣款 | 前端本地扣款后同步服务端 | **服务端扣款为权威**，成功后用返回值回写本地余额 |
| 幂等 | 无 | 每次执行带 `idempotencyKey`，重复提交只执行一次 |
| 大额复核 | 前端创建待复核 | 服务端 ≥¥100,000 直接拦截并写入待复核 |
| 离线降级 | — | 服务端不可用时仍走本地逻辑，演示不中断 |

实测：

```
prepare 500 → T1 指纹/密码（0 分）
prepare 1500 → T2 短信（15 分）
prepare 20000 → T3 短信+人脸（73 分 / 高风险）
prepare 100000 → T4 短信+人脸+人工复核（93 分）
浏览器内转账 100 → 工具返回 { server: true }，余额 976,710.39 → 976,610.39（只扣一次）
```

### 下一步：理财申购/赎回同样服务端权威

当前申购/赎回仍是「本地先扣 → 调服务端同步」。计划改为：先调 `/api/wealth/buy|redeem`，以服务端返回的余额与持仓回写本地，再渲染结果；T+1 到账仍由服务端 `pendingRedemptions` 结算。

### 已完成：理财申购/赎回服务端权威

| 环节 | 之前 | 现在 |
|---|---|---|
| 起购/封闭期/余额/令牌 | 前端校验后本地扣款 | **服务端校验并执行**，错误原样回显（如「封闭期未满（已持有 77 天 / 需 90 天）」） |
| 扣款与持仓 | 本地改 `mockData` 再同步 | 服务端返回 `balance/available/holdings` 回写本地 |
| 赎回 T+1 | 本地造在途记录 | 服务端 `pendingRedemptions` 为准，返回 `arriveDate` |
| 幂等 | 无 | 申购/赎回均带 `idempotencyKey` |
| 验证令牌 | 无 | 金额 ≥¥1,000 时自动先走一次安全验证换令牌 |

实测：

```
申购 稳健增利90天 1000 → server:true，余额 976,510.39 → 975,510.39
赎回 稳健增利90天 500  → 服务端拒绝：封闭期未满（77/90 天）
赎回 均衡配置混合基金 500 → server:true，到账 2026-11-01，余额不变（T+1 在途 490.2）
```

|---|---|---|
