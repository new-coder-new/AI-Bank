## 约定

1. **新增前端模块**：
   - 纯工具/基础设施 → `js/core/`
   - 智能体、模型、记忆、知识库相关 → `js/agent/`
   - 面向用户的功能流程/页面 → `js/flows/`
   - 在 `index.html` 按依赖顺序追加 `<script src="js/<目录>/<文件>.js?v=版本号">`
2. **资源版本**：每次改动前端，把 `index.html` 里所有 `?v=` 统一升一版，避免缓存。
3. **密钥**：只放 `js/core/config.local.js`（git 忽略）；服务端从环境变量读取，二者结构一致。
4. **测试**：`node tests/xxx-suite.js` 直接运行，无需依赖；改对话流程后至少跑 intent / confirm-guard / chip-enum 三个套件。
5. **文档**：面向人的说明统一放 `docs/`，脚本留在 `tests/`。
6. **静态资源白名单**：服务端只放行 `/index.html`、`/favicon.ico`、`/css|js|preview/` 前缀，
   新增资源目录必须落在这些前缀下，或同步修改 `server/index.js` 的 `isAllowedStatic`。

## 数据持久化

服务端不再是纯内存库，业务数据落盘保存，**重启进程 / 重新部署都不会丢**。

| 项目 | 说明 |
|---|---|
| 数据文件 | `data/db.json`（`data/` 已加入 .gitignore，不进仓库） |
| 读取时机 | 服务启动时自动读取；文件不存在才用初始种子 |
| 写入时机 | 任意写接口成功后立即原子写入（临时文件 + rename） |
| 结构升级 | 读取时与种子做深合并，新增字段自动补齐，旧数据不丢 |
| 重置数据 | `POST /api/reset` 恢复种子并覆盖数据文件 |
| 自定义路径 | 环境变量 `BANK_DB_FILE=/your/path/db.json` |
| 容器部署 | Dockerfile 声明 `VOLUME ["/app/data"]`，并设置 `BANK_DB_FILE=/app/data/db.json`；部署时把云盘/卷挂到 `/app/data` 即可跨重建保留 |

联系人相关接口（前后端双向同步）：

```
GET  /api/snapshot            含 contacts（与本地做并集，本地优先）
POST /api/contact/add         新增（卡号去重）
POST /api/contacts/save       整表保存（前端增删改后调用）
POST /api/contact/delete      按姓名/卡号删除
```

### 前端业务流水同步（鲜花 / 定时转账 / 预算）

| 数据 | 存储位置 | 同步方式 |
|---|---|---|
| 鲜花订单 | `userProfile.flowerOrders` | `saveUserData()` → `POST /api/clientstate`（500ms 防抖） |
| 定时转账 | `userProfile.scheduledTransfers` | 同上 |
| 预算 | `userProfile.budgets` | 同上；启动合并时**以服务端为准** |

- 快照接口 `GET /api/snapshot` 返回 `clientState`，启动时按 id 做并集（本地优先），预算取服务端值
- 清缓存 / 换设备后：联系人、鲜花订单、定时转账、预算都能从服务端恢复

### 识别层拆分约定

| 文件 | 职责 | 是否调用模型 |
|---|---|---|
| `js/flows/guide-rules.js` | 服务菜单、关键词表、正则判断、名称解析 | ❌ 不调 |
| `js/flows/guide-ai.js` | 意图路由、槽位抽取、允许/禁止判定、中文数字解析 | ✅ 调 |
| `js/flows/guide.js` | 会话状态机、卡片渲染、追问与确认 | 仅通过调用 `guide-ai.js` |

新增识别逻辑时：纯本地判断放 `guide-rules.js`，任何 `guideLLMJson` 调用放 `guide-ai.js`，流程与渲染留在 `guide.js`。
